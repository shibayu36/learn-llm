# 内部表現の可視化計画

## 目的と進める順番

学習したモデルがtokenをどう配置し、文脈を受けてその表現をどう変えるかをグラフィカルに観察する。

予測性能の評価は `plan.md` の「評価のそろえ方」で扱う。まずはStage 3のvalidation lossの記録を整え、その後に次の順で可視化する。loss曲線は評価のための図とし、ここでは内部表現を扱う。

1. Token embeddingの地図：学習済みの埋め込みで、どのtokenが近くにあるかを見る。
2. Hidden stateの軌跡：同じtokenでも、文脈と層によって表現がどう変わるかを見る。

最初は1つの学習済みモデルを対象にする。層を進める変化と、学習ステップを進める変化は区別し、複数の学習チェックポイントの比較は後で検討する。

## 1. Token embeddingの地図

### 見たいこと

似た使われ方をするtokenが近くに集まるか。選んだtokenの近傍には何があるか。

現在のTokenizerは1文字1tokenなので、点は単語ではなく文字を表す。最初の候補は「長・短」「高・低」「東・西」。意味が反対でも、同じ話題や似た文型で使う文字が近くに配置されるかを観察する。意味だけでなく、表記や出現頻度に関係するまとまりもあり得るものとして読む。

候補選定時に `l1h1-s5000-lr1e-3` の元の64次元の埋め込みで測ったコサイン類似度は、長・短が0.472、高・低が0.419、東・西が0.448だった。これらの6文字だけで投影せず、ほかの頻出文字も含めて描き、対象の組を強調する。2次元でも近くに見えるとは限らず、近さの理由は観察から立てる仮説として扱う。

### 見せ方

- `tok_emb.weight` を取り出し、2次元へ投影した散布図をHTMLで描く。位置埋め込みは加えない。
- 文字のラベルを表示し、検索した文字と、選んだ文字の近傍を強調する。出現回数で表示を絞れるようにする。
- 近傍は元のベクトルのコサイン類似度で求め、上位の文字と類似度を併記する。2次元の図だけで近さを判断しない。
- 投影はPCAとUMAPを切り替える。PCAは全体の散らばりの大きい方向を見る用、UMAPは近傍のまとまりを見る用。PCAの2軸の寄与率が低く近傍が図に出なかったため、UMAPを足した（2026-09-26）。

### 残すもの

対象run・選んだ文字・散布図・元の空間での近傍一覧・観察したまとまりを記録する。意味の近い文字が集まらなかった場合も、そのまま結果として残す。

参考：TensorBoardのEmbedding Projector: https://www.tensorflow.org/tensorboard/tensorboard_projector_plugin?hl=ja

## 2. Hidden stateの軌跡

### 見たいこと

同じtokenの表現が、前にある文脈を取り込みながら各層でどう変わるか。文脈の違う例どうしが、どの層で離れたり近づいたりするか。

1層モデルではブロックの前後を観察できる。複数層にわたる軌跡はStage 4で層を積んでから扱う。

### 入力と取り出す位置

入力は次の6文とする。前文を含めた文脈の違いによって、同じ「行」と「の」の表現がどう変わるかを観察する。後ろの2文は、前文と単語を入れ替えて、どちらが効いているかを分けるためのもの。

```text
お金を預けたい。銀行の口座を開く。
休暇を楽しもう。旅行の予定を立てる。
処理が完了した。実行の結果を確認する。
書類を受領した。発行の日付を確認する。
処理が完了した。銀行の口座を開く。
お金を預けたい。実行の結果を確認する。
```

- 前文はすべて8文字。対象は10文字目の「行」と11文字目の「の」（0始まりの位置9・10）にそろえる。
- 「行」は直前の文字も異なり、「の」は直前の「行」まで同じ。この2つの位置を分けて観察する。
- GPTのCausal Attentionでは対象文字より後ろを参照できないため、区別したい文脈は対象文字の前に置く。
- Layer 0はtoken embeddingとposition embeddingを足したブロックへの入力、Layer 1以降は各TransformerBlockの出力とする。最後の `final_norm` より前でそろえる。
- 同じtoken・同じ位置ならLayer 0は同じベクトルから始まる。位置の違いと文脈の違いを混ぜない。
- 入力文と対象位置は `data/hidden-state-sentences.json` に置く。各層の値は `register_forward_hook` で `TransformerBlock` の入出力から取り出し、モデルのコードは変えない。可視化はモデル実装から独立させ、層が増えても同じコマンドで動くようにする。
- 最初の4文では前文と「銀行・旅行・実行・発行」の両方が異なるため、表現の差を前文だけの効果とは解釈しない。どちらが効いているかは、前文と単語を入れ替えた後ろの2文と比べて確かめる。

### 見せ方

hidden stateはベクトルを眺めても意味が読めない。「何に使われるか」「何に似ているか」を読める形にして観察する（2026-09-26に方針変更。理由は後述）。

- 次の文字の予測（logit lens）：各層のベクトルに `final_norm` と `out_head` を掛け、次の文字の上位10と確率を出す。文脈で予測がどう変わったかを読む。層が増えたら、層を進むごとに予測がどう絞られるかを見る。
- 近い文脈：validationデータの先頭4万位置の各層のベクトルを集め、対象ベクトルにコサイン類似度で近い上位10を、前後の文字付きで表示する。同じ文字でも文脈によって「どの使われ方の仲間」になるかを読む。embeddingの地図の近傍一覧の、文脈版にあたる。
- 元のベクトルでも、同じ層にある文脈の異なる対象tokenどうしのコサイン類似度を確認する。
- 対象位置ごとに表のページにする。文ごとに1行、層の選択でその層の予測と近傍に切り替える。冒頭に「同じ「行」が文脈でどう読まれ、何と同じ扱いになるか」を確かめる表だと説明する。

最初はPCAで各層の点を線で結ぶ軌跡図を作ったが、「ブロックを通ると文脈で変わる」はAttentionの実装上そうなるだけで、学習の中身について何も言わないためやめた。1層で試した予測と近傍は、「銀行・旅行のあとの行は動詞の行う・行った、実行・発行のあとの行は複合語の行」と読める情報が出た。

### 残すものと読み方

対象run・入力文・対象tokenと位置・取り出した層・各層の予測上位・近い文脈・元の空間での類似度を記録する。

予測や近傍は文脈による表現の変化を観察する入口とする。「この層が特定の知識を獲得した」「この情報を回答に使った」とまでは判断しない。

参考の見せ方：BERTの層ごとのcontextual embedding: https://medium.com/@sonali.chowdhury.2013/context-is-everything-tracing-embedding-shifts-through-attention-70fa45514eca

## 記録先と見直す条件

- 図と元データは対象の `runs/<run_name>/` に保存する。`runs/` をcommitしない既存方針に従い、残したい条件・数値・観察は `visualization-results.md` に書く。予測性能の記録 `evaluation-results.md` とは分ける。
- Tokenizerを変更したら、点の単位と観察する入力を見直す。単語を複数tokenで表す場合は、単語を代表させる位置や集約方法を別途決める。
- 複数run・学習チェックポイントへ比較を広げる場合は、比較対象と投影の基準を固定する方法を改めて決める。独立に学習したモデルの座標を、そのまま同じ意味の軸として重ねない。
