# KVキャッシュの結果

`generate`（毎回全文を入れる）と `generate_with_kv_cache`（まだ入れていない文字だけを入れる）で、生成時間とキャッシュの大きさを比べる。設計は `kv-cache-plan.md`。モデルの質の結果ではないので `evaluation-results.md` には入れない。

## 測定条件

- モデルは `ku-nlp-gpt2-small-char`（12層・12ヘッド・768次元、context 1,024）
- `uv run main.py generate "日本の首都は" --run-name ku-nlp-gpt2-small-char --max-new-tokens N`（`--kv-cache` あり・なし）。temperature 0
- CPU（Apple M5 Pro）。生成時間はモデルの読み込みを含まず、`generate` の呼び出しだけ
- 生成した文章はすべての条件で `--kv-cache` の有無によらず同じ

## 生成時間

### キャッシュなしは長く生成するほど1文字が遅くなり、キャッシュありは長さに関係なく一定

| 生成文字数 | キャッシュなし | キャッシュあり | 倍率 |
|---|---|---|---|
| 100 | 3.59秒（35.9ms/文字） | 1.51秒（15.1ms/文字） | 2.4倍 |
| 200 | 9.29秒（46.4ms/文字） | 3.12秒（15.6ms/文字） | 3.0倍 |
| 300 | 17.01秒（56.7ms/文字） | 4.62秒（15.4ms/文字） | 3.7倍 |

キャッシュなしでは、i文字目を生成するときにprompt + (i-1)文字の全文をモデルに通し直す。1回あたりの計算量が文字数に比例して増えるので、1文字あたりの時間が 35.9 → 46.4 → 56.7ms と伸び、合計は文字数の2乗に近い形で増える（100文字の4.7倍で300文字）。

キャッシュありでは、毎回入れるのは新しい1文字だけで、埋め込み・Attentionのクエリ・キー・値の射影・フィードフォワード・出力ヘッドはすべて1文字分しか計算しない。過去の文字のキーと値はキャッシュから読むだけなので、1文字あたりの時間は約15msで変わらず、合計は文字数に比例する。文字数が増えるほどキャッシュの効果（倍率）が大きくなるのはこのため。Attentionのスコア計算（新しい1文字のクエリ × 過去全部のキー）だけは過去の文字数に比例して増えるが、300文字程度では他の計算に埋もれて見えない。
